# v6.16 — Scope `closed_tabs` to its Orbit

**Goal:** Stop recently-closed tabs from crossing Orbits. A tab closed in *Work* must not appear in —
or reopen into — *Personal*.

**Why:** Orbits promise isolated browsing profiles, and that promise is kept for `tabs`, `history`,
`bookmarks`, `home_shortcuts`, `credentials` and `downloads`. It is **not** kept for `closed_tabs`:
the entity has no `orbitId` and the DAO reads unfiltered
(`SELECT * FROM closed_tabs ORDER BY closedAt DESC …`), so every Orbit sees every other Orbit's closed
tabs, and `onReopenClosed` reopens into whichever Orbit happens to be active. Found 2026-08-14 while
writing [docs/DATA-MODEL.md](../../DATA-MODEL.md); Tier 1 on [ROADMAP.md](../../ROADMAP.md).

**Not an incognito leak.** `TabManager.closeTab` already gates the insert on `!isIncognitoId(id)`, so
incognito tabs are never recorded. This is a normal-browsing cross-*profile* leak.

A second, related defect: `trimTo(100)` is also global, so a busy Orbit can evict another Orbit's
entries from the ring.

## Design

### `data/ClosedTabEntity.kt`
```kotlin
@Entity(tableName = "closed_tabs")
data class ClosedTabEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val url: String,
    val title: String,
    val closedAt: Long,
    val orbitId: Long? = null,
)
```
Nullable, matching `tabs`/`history`/`bookmarks`. A `NULL` row matches no `WHERE orbitId = :orbitId`,
so unattributed rows are invisible — **fail-closed**.

### `data/ClosedTabDao.kt`
```kotlin
@Query("SELECT * FROM closed_tabs WHERE orbitId = :orbitId ORDER BY closedAt DESC, id DESC LIMIT :limit")
fun observeRecent(orbitId: Long, limit: Int): Flow<List<ClosedTabEntity>>

/** Ring semantics PER ORBIT: one busy Orbit must not evict another's entries. */
@Query(
    "DELETE FROM closed_tabs WHERE orbitId = :orbitId AND id NOT IN " +
        "(SELECT id FROM closed_tabs WHERE orbitId = :orbitId ORDER BY closedAt DESC, id DESC LIMIT :max)"
)
suspend fun trimTo(orbitId: Long, max: Int)

@Query("DELETE FROM closed_tabs WHERE orbitId = :orbitId")
suspend fun deleteForOrbit(orbitId: Long)
```
`deleteById` and `clear` unchanged (`clear` still backs the Black Hole wipe).

### Migration 21 → 22

```kotlin
db.execSQL("ALTER TABLE closed_tabs ADD COLUMN orbitId INTEGER")
db.execSQL("DELETE FROM closed_tabs")
```

**Deliberate deviation from the backfill convention.** Migrations 15→16, 16→17 and 18→19 backfilled
existing rows to the first Orbit. Here that would be wrong: legacy rows are *unattributable* (they were
global), so assigning them to the first Orbit would **preserve the very leak this release fixes** —
Work URLs would surface in Personal. Recently-closed is ephemeral, low-value data, so discarding it is
the privacy-correct choice. Documented in the migration comment and in DATA-MODEL.md.

### `browser/TabManager.kt`
```kotlin
val closing = _tabs.value.find { it.id == id }
val closingOrbitId = closing?.orbitId
if (closing != null && !isIncognitoId(id) && closingOrbitId != null) {
    closedTabDao.insert(
        ClosedTabEntity(url = closing.url, title = closing.title, closedAt = now(), orbitId = closingOrbitId)
    )
    closedTabDao.trimTo(closingOrbitId, 100)
}
```
Uses the **closing tab's own** `orbitId`, not the active Orbit, so closing a tab that belongs to another
Orbit records it against the right one. The `closingOrbitId != null` guard covers the documented
first-install window where `initialize` can create a tab before an Orbit is seeded; such a tab produces
no recently-closed row rather than an invisible orphan.

### `BrowserViewModel.kt`
```kotlin
val recentlyClosed: StateFlow<List<ClosedTabEntity>> = activeOrbitId
    .flatMapLatest { orbitId -> closedTabDao.observeRecent(orbitId, 100) }
    .stateIn(viewModelScope, SharingStarted.Eagerly, emptyList())

fun onReopenClosed(entry: ClosedTabEntity) {
    viewModelScope.launch {
        tabManager.newTab(entry.url, orbitId = entry.orbitId ?: activeOrbitId.value)
        closedTabDao.deleteById(entry.id)
    }
}
```
`Eagerly` is retained (the tab switcher reads it immediately). Reopen prefers the entry's own Orbit.

Add `closedTabDao.deleteForOrbit(id)` to the Orbit-deletion cleanup beside the existing
`historyDao`/`bookmarkDao`/`homeShortcutDao`/`credentialRepository` calls, so deleting an Orbit no
longer leaves its closed tabs behind.

## Testing

`TabManagerTest`
- a closed normal tab records `orbitId` = the **closing tab's** orbit (not the active one)
- an incognito tab still records nothing (regression guard on the existing gate)
- a normal tab with `orbitId == null` records nothing

`BrowserViewModelOrbitTest`
- close a tab in Orbit A → visible in A's `recentlyClosed`; switch to Orbit B → **not** visible
- reopen from A reopens into A
- deleting an Orbit removes its closed-tab rows

`FakeClosedTabDao` mirrors the new signatures, including **per-Orbit** trim and `orbitId = NULL` never
matching a filter.

Migration `MigrationTestHelper` case 21 → 22: column added, and pre-existing rows are gone.
(Instrumented — needs a device, so expect *compiled, not run*.)

## Non-goals

- Scoping `reading_list` (the other known gap — separate decision, see ROADMAP Tier 1).
- Any UI change: the Recently-closed list looks identical, it just shows the right rows.
- Preserving legacy closed-tab entries across the upgrade (deliberately discarded, above).
